# 山西 × 江西 2026 双人旅行计划

移动端优先的静态行程网站：**2026-11-27 晚梧州出发，2026-12-06 必须回到梧州**。

路线：梧州 → 广州 → 太原（晋祠、沾串）→ 平遥 → 景德镇 → 婺源石城 → 三清山 → 上饶 → 广州 → 梧州。

## 网站功能

- 10天9晚的完整每日时间表、住宿与高德导航入口。
- 11月28日 18:00 太原“小溅沾串”用餐安排及备选。
- 按区域筛选日期；展开每日时间安排。
- 两人预算交互估算（¥10,900—18,900，非实时成交价）。
- 机票/高铁/住宿/索道预订核对清单，自动保存当前浏览器。
- 每日私人备注，同样只保存当前浏览器，不会上传云端。
- 一键导出 .ics 日历；浏览器打印 / 保存 PDF。
- 手机浏览器支持添加到主屏幕及网页离线缓存（打开一次后，重新进入可能离线可用）。

## GitHub Pages 部署

1. 在 GitHub 账号 **`lys20001205`** 下新建公开仓库，推荐名称 `shanxi-jiangxi-trip-2026`。
2. 将本目录的 `index.html`、`sw.js`、`manifest.webmanifest`、`assets/icon.svg` 上传至仓库默认分支（如 `main`）根目录。
3. 打开仓库 **Settings → Pages**，在 **Build and deployment** 选择 `Deploy from a branch`，分支选择 `main`，目录选择 `/(root)`，点击 **Save**。
4. Pages 发布完成后，预期地址为 `https://lys20001205.github.io/shanxi-jiangxi-trip-2026/`。**此地址只有在仓库创建并成功发布之后才会生效。**

如果你已经新建了空仓库，可直接把仓库 URL 发到聊天里，便于连接的 GitHub 工具将网页文件提交到对应仓库。当前 GitHub 连接不提供“新建仓库”或“启用 Pages”动作，因此这两步需要仓库所有者在网页端操作。

## 后续修改方式

行程、每段时间、餐厅和预算都集中在 `index.html` 底部的 `TRIP`、`BUDGET`、`TASKS` 数组，修改之后提交即可更新网页。无需 Node.js、React、服务器或构建流程。

如果更新网页内容后离线缓存没有刷新，可在 `sw.js` 中把 `shanxi-jiangxi-trip-2026-v1` 改为 `v2`。

## 重要限制

- 网站内容是规划，不是已经出票或预订；尤其是 2026-11-30 太原→景德镇航季直飞，已由景德镇市民航建设服务中心发布计划，但指定日期实际机票库存和票价需另查。
- 公共 GitHub Pages 网页**对所有人可见**。网站仅放旅行计划，不要在行程公开内容或仓库里保存证件号、手机号、订单号。私人备注只存在各自设备浏览器 localStorage 中，**不跨设备同步**。
- 源代码中的景点、地址与商业信息均可能变化，应在付款前复核官方信息。
- 插画为原创 SVG，不代表真实景点照片，无外部资源依赖。
